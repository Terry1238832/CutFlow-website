CutFlow 1.1.3 发布检查

检查日期：2026-09-12 / 2026-09-13。版本：1.1.3（build 6）。

本次修复

  1. 复制尚未完成时按住 Command-V，现在同时抑制重复按下和对应抬起；只有松开并重新按下才能移动，避免复制完成后仍按住的 V 自动触发移动。
  2. 修正改写按键后的 Unicode 字符。实测零长度 keyboardSetUnicodeString 不会清除已有字符，现在明确设置为目标命令的 c / v。
  3. 新安装默认关闭实验淡化，保留既有用户保存的开关设置。界面版本号从应用清单读取。

已通过

范围证据与边界

键盘事件处理按下/抬起映射、缓存字符、长按防重复、提前粘贴、复制超时、普通复制粘贴、修饰键、文字保护、跨应用/文件管理器、取消/暂停/停止、监听中断、视觉中断
测试隔离事件测试使用独立命名剪贴板和内存中的 CGEvent；不安装全局监听、不发送按键。验证生产处理函数，不等同于物理键盘端到端测试
Finder 多项目移动实机用原生 Command-C / Option-Command-V 移动 2 个文件和 1 个含文件的文件夹，包含中文及空格；源路径消失，目标 SHA-256 与基线一致
Finder 普通移动撤销上述移动用 Command-Z 撤销后，3 个源文件内容恢复，目标无测试数据（Finder 的 .DS_Store 除外）
同名冲突停止Finder 显示冲突对话框；选择停止后，源文件和原有目标文件哈希均不变

打包Apple Silicon / Intel Release 编译、通用二进制、本地代码签名、Info.plist 和 ZIP 完整性检查通过

未通过或未完成的验证

  • Gatekeeper 正常接受：未通过。本包是 ad-hoc 临时签名、未公证；用户明确选择先分发需要手动批准安装的版本。正式 Release 标签不代表获得 Apple 签名、公证或审核。
  • 1.1.3 物理键盘经过全局 event tap 的端到端回归未完成；此前 1.0.1 的 Command-X / Command-V 物理键盘移动由用户验证过。本轮事件函数测试和 Finder 原生操作测试分别覆盖两端，不能替代完整链路验证。
  • “保留两者”后的再次撤销尝试未恢复原来源路径，因此未记为通过。数据仍在目标目录中；不能保证所有冲突处理都可撤销。

  • 本轮未复测辅助功能撤销/重新授权、登录启动、重复实例唤起、ForkLift 实机、Intel 真机、macOS 13–25、跨磁盘/网络盘、只读目录、大量文件及长时间运行。

发布范围

按用户选择发布未公证安装包，披露上述边界。不宣传所有环境均已验证，也不声称 macOS 无需人工批准即可打开。Finder 负责文件操作和冲突处理，CutFlow 不直接移动、删除或改写文件。
